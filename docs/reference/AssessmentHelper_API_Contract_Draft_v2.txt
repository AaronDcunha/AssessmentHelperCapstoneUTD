CONVENTIONS
===========
Q = query; B = JSON body; R = response. ? = optional. {id} = opaque path ID.
Fields/enums below are proposals. Typed shapes describe data, not executable JSON.
List<T> = {items:T[],pageInfo:{nextCursor:string|null,hasMore:boolean}}.
All lists accept cursor?/limit?; proposed default 20, maximum 100. Counts cover all
matching records, not just the current page. Dates: YYYY-MM-DD; timestamps: UTC ISO
8601. Include IANA timeZone with schedules. Exact deadline boundaries remain TBD.

Standard errors: {error:{code,message,fieldErrors?,requestId?}}.
400 invalid request; 401 logged out/inactive; 403 forbidden; 404 unavailable record;
409 duplicate/stale revision/invalid transition; 422 validation; 413/415 upload errors;
429 throttled. Auth.js retains its own error/redirect contract.
Reads/updates: 200; creates: 201; deletes: 204. Async jobs: 202 + operation ID.
Use no-store for private data; enforce CSRF/origin checks on cookie-based mutations.

Security applies to EVERY route: active session, effective permission, organizational
scope and record ownership. Derive actor from session. Validate/allow-list inputs;
never trust browser ownership, roles, timestamps or completion states. Use revisions
for concurrent edits and idempotent transactions for retried workflow mutations.
Admin inherits AC + Faculty access; AC inherits Faculty access. /me remains personal.
Final permission keys, AC scope, revision/idempotency details require agreement.

RELATIONAL SCHEMA CROSS-CHECK
=============================
Checked AssessmentHelper_Relational_Schema.drawio. API camelCase can map to its
snake_case fields; nested responses are authorized joins, not extra tables.
- User.id -> app_user.user_id. Professor uses that same ID through professor.user_id;
  teaches.professor_id and signup/candidate/feedback professor references identify it.
  No username column exists or is needed. app_user.email is unique; name is not.
- Roles/grants -> role, user_role, permission, role_permission. permissions uses
  permission_key. role.key/description are proposed additions, not current fields;
  use role_id/name or agree stable keys. Inheritance needs application/schema support.
- Section.course -> course_section joined to course; title maps to course.name.
  courseCode is derived from prefix/number; course level needs an agreed derivation.
  Timetable -> class_meeting. Date occurrences require calendar/exception rules.
- Cycle -> evaluation_cycle; signup -> evaluation_signup; Observation.id ->
  observation.observation_id. cycleId/section/participants can be joined via signup.
  scheduled_at alone does not identify the selected time_option or its end time.
- Persisted proposed meetings -> observation_time_option.time_option_id, starts_at,
  ends_at, observation_id. Pre-signup availability IDs are server-resolved occurrence
  tokens, NOT existing time_option IDs. Signup creates the observation/time options;
  candidate acceptance must reference one of those persisted options.
- Candidate -> observation_candidate. Its current fields track only one send/response;
  attempts, compatible dates and acceptedMeetingOptionId require additional relations.
- Template -> observation_template.template_version_id. Criterion ->
  template_criterion. type maps to question_type; options expand rating_range only
  after its representation is agreed. key/order, scale labels, comment/signature
  configuration and publication applicability are proposed extensions.
- Feedback -> process_feedback. process_rating/difficulties/suggestions exist;
  generic answers, survey version and multiple attachments need extensions. Its
  participant_role column does not resolve dual-role submission/counting policy.
- Notification -> notification. target can derive from observation_id/cycle_id;
  title can derive from type. Other target kinds require an agreed extension.
- evaluation_interval_years -> evaluationIntervalYears; account_status -> accountStatus.
  Semester name derives from year/season. Semester dates/timezone, hiringLevel.active,
  revisions, async operations and idempotency records are not in the current diagram.

Required schema updates: web assessment/answer/history records replacing the old
signed_assessment.signed_file_reference flow; invitation attempts; accepted/final
meeting references; expired-acceptance approvals; AC alerts/resolution; private
feedback attachment metadata. Acknowledgement/finalization details remain conditional.
login_credential is an old local-password proposal, not a requirement for UTD SSO;
future SSO identity linking needs its own agreed mapping to app_user.
allowedActions, eligibility, unread/pending counts and dashboard summaries are derived
server outputs, not necessarily stored columns. occurred must follow agreed reporting/
acknowledgement rules; never infer it merely from a scheduled date or missing form.
This cross-check does not change the diagram or the teammate's Prisma schema.
